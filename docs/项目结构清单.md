# 项目结构清单（带注释）

> 适用于 `smart-assistant-java/`（IPAS 智能助手）。
> 本文档只做"说明"，不改变任何代码。目录与包名均以**当前实际状态**为准。
> 组织方式：前后端分离（`backend/` + `frontend/`）；**后端按"层"分包，前端按"类型"分目录**。

---

## 〇、顶层布局

```
smart-assistant-java/
├── backend/            Spring Boot 后端（Maven 工程根，pom.xml 在这层）
├── frontend/           React + TypeScript + Vite 前端
├── docs/               说明文档（学习文档 / 项目结构清单 / 优化记录 / 答辩面试手册）
├── tools/              辅助脚本（mock_openai.py：本地假 OpenAI 服务）
├── start.sh / start.bat  一键启动前后端（会检查前端依赖是否已装）
├── README.md           使用说明（安装 / 启动 / 验证）
├── .gitignore          项目级忽略规则
└── .navicat-probe.txt  临时探针文件（含凭据，已 gitignore；是否删除待定）
```

**为什么是"前后端分开"**：前端是 React 单页应用、后端是 Spring Boot 服务，
两者互不依赖源码，只通过 `/api`（HTTP）交互，物理分开便于各自独立构建/部署。

### 1.1 后端包结构（`com.ipas.assistant.*`，按"层"组织）

> 依赖方向自上而下：`controller → service → repository/entity`；`common/config/security` 为全局基础设施，被各层引用。

| 包 | 文件数 | 职责 | 代表性类 |
|---|---|---|---|
| `com.ipas.assistant`（根） | 1 | 启动类；也是组件/实体/仓储扫描的基准包 | `AssistantApplication` |
| `common` | 7 | **跨模块基础设施**，不依赖任何业务模块 | `ApiException`、`ErrorBody`、`GlobalExceptionHandler`、`ChatStreamEvent`、`SystemPrompts`、`ModelCatalog`、`Times` |
| `config` | 4 | Spring 配置与启动期绑定 | `AppProperties`、`AgentMemoryConfig`、`JacksonConfig`、`AppVersion` |
| `security` | 6 | 鉴权链（JWT + Spring Security + CORS） | `SecurityConfig`、`JwtService`、`JwtAuthenticationFilter`、`PasswordService`、`AuthUser`、`RestAuthenticationEntryPoint` |
| `controller` | 19 | REST 接口层（薄，只做参数绑定与调用 Service） | 见下方"模块 ↔ 控制器" |
| `dto` | 19 | 请求/响应体；**按模块合并成容器类**（record 为主） | `KbDtos`、`FileDtos`、`NoteDtos`、`SessionDtos`、`StatusResponse` |
| `dto/auth` | 3 | 鉴权专用 DTO | `LoginRequest`、`RegisterRequest`、`TokenResponse` |
| `dto/user` | 2 | 用户资料专用 DTO | `UserOut`、`UserUpdateRequest` |
| `entity` | 14 | JPA 实体（表） | `User`、`Conversation`、`Message`、`Skill`、`Note`、`TodoItem`、`Schedule`、`Course`、`Notification`、`LlmProvider`、`KbCollection`、`KbChunk`、`FileItem`、`AppSetting` |
| `entity/converter` | 1 | JPA 属性转换器 | `LongListJsonConverter`（`List<Long> ↔ JSON 列`） |
| `repository` | 14 | Spring Data JPA 仓储（与实体一一对应） | `UserRepository`、`ConversationRepository`、`MessageRepository`、`KbChunkRepository`… |
| `schedule` | 1 | 定时任务 | `ScheduleReminderJob`（每 30s 扫"5 分钟内即将开始且未提醒"的日程 → 写站内通知） |
| `service` | 25 | 业务服务（模块逻辑集中处） | 见下方"模块 ↔ 服务" |
| `service/agent` | 5 | 智能体装配（第三阶段核心） | `AgentFactory`(`@Profile("!test")`)、`AgentCache`、`AssistantTools`、`SafeCalculator`、`ThinkSplitter` |
| `service/llm` | 1 | 模型工厂（按会话凭据动态构造 ChatModel） | `ChatModelFactory` |
| `service/memory` | 3 | 对话记忆端口（对应 LangGraph Saver） | `ConversationMemoryPort`、`MysqlConversationMemory`、`NoopConversationMemory` |
| `service/rag` | 4 | RAG 检索与切分 | `EmbeddingService`、`RagService`、`RagSourcesBus`、`TextSplitter` |

**合计**：129 个主源码文件（+ 2 个测试文件）。

| 技能 skills | `SkillController` | `SkillService` | `Skill` / `SkillDtos` |

| 课表 courses | `CourseController` | `CourseService` | `Course` / `CourseDtos` |
| 通知 notifications | `NotificationController` | `NotificationService` | `Notification` / `NotificationDtos` |

### 1.3 后端关键约定（改代码前必读）

- **接口契约**：JSON 一律 `snake_case`；错误体 `{"detail": "中文提示"}`；状态码 400 业务校验 / 401 未认证 / 404 不存在（不外泄存在性）/ 422 框架校验；时间是不带时区的 ISO 字符串（存 UTC）。
- **SSE 五类事件**：`token` / `reasoning` / `sources` / `done` / `error`，逐字对齐原版，前端零改动。
- **`@RequestBody` 必须配 `@Valid`**，`@RequestParam` 的校验必须给控制器类加 `@Validated`（否则静默失效）。
- **`DataDirProvider` 是数据目录的唯一来源**（库中 `system.data-dir` ＞ yml 默认），改完立即生效；不要直接读 `AppProperties.dataDir()`。
- **Agent 相关 Bean 标 `@Profile("!test")`**：`MysqlSaver` 构造即连库，契约测试（不依赖 MySQL）整体排除它们。
- **服务层 `requireOwned(userId,id)`** 取不到一律抛 404（不抛 403），避免泄露资源是否存在。

## 二、前端 `frontend/`

```
frontend/
├── index.html            页面挂载点
├── package.json / package-lock.json   依赖与脚本（dev / build）
├── tsconfig.json         TS 配置
├── vite.config.ts        Vite 配置（dev 端口 5174；`/api` 代理到 http://127.0.0.1:8002）
└── src/
    ├── main.tsx          React 入口
    ├── App.tsx           应用根组件（路由）
    ├── i18n.tsx          中英文文案表
    ├── styles.css        全局样式（单文件，按模块分区注释）
    ├── types.ts          全局 TypeScript 类型
    ├── theme.ts          主题（明/暗）
    ├── toast.ts          轻提示
    ├── chime.ts          提示音
    ├── globalModel.ts    全局模型选择状态
    ├── api/              HTTP 层（**与后端契约的唯一对接点**）
    │   ├── client.ts       fetch 封装 + SSE（fetch-stream）解析
    │   └── index.ts        各模块 API 定义（authApi / noteApi / chatApi / calendarApi …）
    ├── components/       可复用组件（24 个，扁平放置）
    └── pages/            路由页面（9 个）
```

### 2.2 `src/pages/`（9 个）

`CalendarPage`（日历）、`KnowledgePage`（知识库）、`NotesPage`（笔记）、`SchedulePage`（日程）、`SkillsPage`（技能）、`TimerPage`（计时器）、`TimetablePage`（课表）、`TodosPage`（待办）、`WeatherPage`（天气）。

> **前端约定**：所有对后端的调用集中在 `src/api/`；改动后端契约前，先核对这里的字段名与事件类型（前端坚持"零改动"原则）。
