## 第 0 章 先用一句话说清：这个项目是什么

它是一个**智能个人助理**：网页上能和 AI 聊天（支持上传文件、挂"技能"、查"知识库"），
还有待办 / 笔记 / 日程 / 课表 / 日历 / 天气 / 计时器等功能。

它由两部分组成：

- **后端**（`backend/`）：Java + Spring Boot，提供 `/api/...` 接口，管数据、调大模型、做检索。
- **前端**（`frontend/`）：React + TypeScript，浏览器里的界面，所有数据都通过 `/api` 找后端要。

一句话架构：**浏览器（React） ⇄ HTTP/SSE ⇄ 后端（Spring Boot） ⇄ 数据库（MySQL）/ 大模型（Ollama 或云端）**。

> 设计目标：前后端之间有一份**明确的接口契约**（字段命名、错误格式、状态码），
> 前端严格按这份契约对接，后端据此逐条实现并固化进测试（`ApiContractTest`）。

## 第 1 章 技术栈总览（每个都先讲"是什么 + 为什么用它"）

### 1.1 后端

> **【本版本新增的技术点】**
> - **虚拟线程**：`spring.threads.virtual.enabled=true` —— 模型调用几乎全是"等 IO"，虚拟线程让并发更省内存（前提是先确认没有 `synchronized` 包住 IO，否则会 pinning）。
> - **springdoc**：接口文档 `/swagger-ui.html`（**必须配 bearerAuth 方案**，否则 UI 里点任何接口都只返回 401）。
> - **Caffeine**：两处有界缓存 —— Agent 缓存、运行时配置快照（写入即失效，保证"保存立刻生效"）。
> - **可选后端**：MinIO（文件存储）、pgvector（向量检索）—— 都是"改一个配置值切换"，默认全关、不配也能跑。
> - **前端 vitest + jsdom**：`npm test` 跑单测（SSE 帧解析 / 主题归一化 / 全局模型偏好）。

## 第 2 章 启动时发生了什么（把"装配"讲透）

入口类：`backend/src/main/java/com/ipas/assistant/AssistantApplication.java`

```java
@SpringBootApplication   // = @Configuration + @EnableAutoConfiguration + @ComponentScan
public class AssistantApplication {
    public static void main(String[] args) { SpringApplication.run(AssistantApplication.class, args); }
}
```

启动流程（**后面所有章节都建立在这条链上**）：

1. **组件扫描**：Spring 从 `com.ipas.assistant` 这个包往下扫描，凡是带
   `@Component / @Service / @Repository / @RestController / @Configuration` 的类，都被创建成 **Bean**（对象），放进"容器"。
2. **依赖注入（DI）**：Bean 的构造方法参数会被 Spring 自动填上（不用你 `new`）。
   例如 `NoteService(NoteRepository repo, ...)` 里的 `repo` 是 Spring 给的。
3. **读配置**：`application.yml` 里的值被绑定到 `config/AppProperties`（`@ConfigurationProperties("app")`）。
   这就是**为什么配置只写在一处、全项目都能拿到**。
4. **建表**：`spring.sql.init` 会在启动时执行 `src/main/resources/db/schema-mysql.sql`（脚本里全是 `CREATE TABLE IF NOT EXISTS`，可重复执行）。
5. **装安全过滤链**：`security/SecurityConfig` 定义"哪些接口要登录、怎么校验 token"。
6. **启动定时任务**：`schedule/ScheduleReminderJob` 每 30 秒扫一次"即将开始的日程"→ 写站内通知。
7. **内嵌 Tomcat 开始监听** `127.0.0.1:8002`，开始接收请求。

> 关键心智模型：**Spring 就是一个"大工厂 + 依赖自动分配器"**。你写类和注解，它负责创建与连接。

## 第 3 章 后端分层：一次普通请求的完整旅程

后端按**层（layer）**分包，各层职责单一、单向依赖：

```
controller  →  service  →  repository  →  entity/DB
（收请求）     （业务逻辑）    （数据访问）     （表）
        ↖________________ common / config / security（全局基础设施）________________↗
```

以「查询待办列表」`GET /api/todos` 为例：

```
浏览器
  │  GET /api/todos  带 Authorization: Bearer <token>
  ▼
[过滤器链] security/JwtAuthenticationFilter   ← 解析 token，把当前用户放进 SecurityContext
  ▼
controller/TodoController           ← @GetMapping，参数绑定，调用 Service
  ▼
service/TodoService                 ← 业务逻辑（排序规则：未完成优先）
  ▼
repository/TodoRepository           ← Spring Data JPA，方法名即查询（findByUserId...）
  ▼
MySQL 表 todos
  ▲
  └─ 查出来的是 entity/TodoItem（Java 对象），再由 dto/TodoDtos 转成"给前端的形状"
  ▼
响应 JSON（snake_case，如 {"id":1,"is_done":false,...}）
```

**为什么要分 DTO（Data Transfer Object）？**
实体（`entity`）对应数据库表；DTO 对应**接口的长相**。两者分开，才能做到"改数据库不影响前端契约"。

**各层速记**：

| 层 | 目录 | 你会在这里看到 | 一句话 |
|---|---|---|---|
| 控制器 | `controller/` | `@RestController`、`@GetMapping` | "门卫 + 前台"，只收参数、转给 Service |
| 服务 | `service/` | `@Service`、业务判断 | "大脑"，真正的逻辑在这 |
| 仓储 | `repository/` | `interface XxxRepository extends JpaRepository<...>` | "库管"，只和数据库打交道 |
| 实体 | `entity/` | `@Entity`、`@Id`、`@Column` | "表在 Java 里的样子" |
| 传输对象 | `dto/` | `record` 为主 | "接口的输入输出形状" |
| 基础设施 | `common/ config/ security/` | 异常、配置、鉴权 | 全局共用 |

### 3.1 几个"初学者最容易懵"的点

- **`@RequestBody` 与 `@Valid`**：前者把 JSON 变成对象，后者触发参数校验。
  本项目踩过的坑：**只写 `@RequestBody` 忘了 `@Valid`，校验注解会静默失效**。
- **错误响应统一格式**：`common/GlobalExceptionHandler` 把所有异常翻译成
  `{"detail": "中文提示"}` + 正确状态码（400 业务错 / 401 未登录 / 404 不存在 / 422 参数格式错）。
  这是为了**让前端错误处理逻辑与接口契约保持一致**。
- **`record`**：Java 16+ 的"不可变数据类"，一行顶十几行 getter/equals。项目里 DTO 大量使用。
- **Lombok**：实体上用 `@Getter @Setter`（**不要用 `@Data`**，原因见 `pom.xml` 注释——JPA 实体的 equals 有坑）。

## 第 4 章 数据是怎么存的（JPA + MySQL）

- 14 张表定义在 `entity/` 下，每张表一个类，用注解映射：

```java
@Entity
@Table(name = "todos")
public class TodoItem {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    @Column(name = "user_id") private Long userId;
    @Column(name = "is_done") private Boolean done;
    // ... getter/setter（Lombok 生成）
}
```

- 14 张表（`db/schema-mysql.sql`）：`users`、`conversations`、`messages`、`todos`、`notes`、
  `schedules`、`courses`、`skills`、`files`、`kb_collections`、`kb_chunks`、`notifications`、
  `llm_providers`、`app_settings`。
- **仓储只需声明接口**，方法名自动变成 SQL：
  `findByIdAndUserId(...)` → `SELECT ... WHERE id=? AND user_id=?`。不用手写 SQL。
- **`@Query`** 用在复杂查询（如跨会话搜索、LIKE 匹配）。
- **时间戳**：实体上用 `@PreUpdate` 自动更新 `updated_at`；坑点是"事务内构造响应时它还没触发"，
  所以服务里要显式 `repository.flush()`。

## 第 5 章 安全与鉴权（Spring Security + JWT）

**JWT 是什么**：登录成功后，服务器签一张"电子通行证"（一段字符串），前端存下来，
以后每次请求都放在请求头 `Authorization: Bearer <token>` 里；服务器验签即可确认"你是谁"，无需查会话表。

流程：

```
POST /api/auth/login  {username, password}
        ▼
AuthService：查用户 → BCrypt 校验密码 → JwtService 签发 token
        ▼
返回 {access_token, token_type:"bearer", ...}
        ▼
前端把 token 存在本地，之后每个请求带上
        ▼
security/JwtAuthenticationFilter：解析 token → 得到 userId → 放进 SecurityContext
        ▼
controller 里用 @AuthenticationPrincipal AuthUser me 拿到当前用户（各业务只操作"自己的"数据）
```

相关文件：`security/`（6 个类）、`controller/AuthController`、`service/AuthService`。

> 初学者提示：**不要在任何地方打印或用 token 原文**；生产环境 `SECRET_KEY` 必须用环境变量覆盖。

## 第 6 章 大模型是怎么接进来的（Spring AI + SAA + Ollama）

这是本项目最"高级"的部分，但拆开看并不难。

### 6.1 两个"模型来源"

- **本地 Ollama**（默认）：`provider=ollama`，模型如 `qwen3:8b`。
- **云端 OpenAI 兼容平台**：`provider=cloud`，兼容智谱 / DeepSeek / 百炼 / 硅基流动 / OpenAI（只换 `base-url` 和 `api-key`）。

**关键设计：模型是"运行时按会话动态构造"的**，不是启动时定死。
对应 `service/llm/ChatModelFactory`：给 `(provider, model, apiKey, baseUrl, ...)` → 返回一个 `ChatModel`。
这正是**不用 Spring AI starter 自动配置**的原因（自动配置要求启动就配好 api-key）。

### 6.2 Agent（会自己用工具的 AI）

- **ReAct 模式**：模型可以"先思考 → 调用工具 → 看结果 → 再回答"，循环直到给出最终答案。
- 本项目用 **SAA 的 `ReactAgent`** 实现，装配在 `service/agent/AgentFactory`：

```
ChatModel（大脑）          ← ChatModelFactory 按会话凭据 new 出来
  + tools（工具）          ← AssistantTools.forUser(...)：计算器 / 天气 / 待办 / 查知识库…
  + systemPrompt（人格）   ← SystemPrompts.BASE（+ 启用技能的附加指令）
  + memory（记忆）         ← MysqlSaver：按 thread_id = 会话 id 隔离
  + hooks（上下文压缩）    ← 官方 SummarizationHook：太长时把旧对话压成摘要
        ▼
     ReactAgent
```

- **工具**定义在 `service/agent/AssistantTools`：方法加 `@Tool` 就能被模型调用。
  例如 `search_knowledge_base` 就是 RAG 的入口。
- **记忆**在 `service/memory/`：`MysqlConversationMemory` 直接操作 `graph_thread` 表清记忆；
  `MysqlSaver` 把每轮消息存进 MySQL（按会话 id 隔离）。
- **Agent 缓存** `service/agent/AgentCache`：构建 Agent 很贵，用"8 维复合键"（会话/供应商/模型/技能集/知识库集/思考开关/预算/id）缓存复用。

### 6.3 RAG（让 AI 会"翻自己的资料")

> **【本版本新增：检索这一层做完了哪些事】**
> 1. **混合检索**：向量通道 + MySQL 全文通道（必须用 **ngram 解析器**，否则中文整段被当成一个词），两路结果用 **RRF 按名次融合**（不是按分数 —— 两种分数量纲不同，名次才可比）。
> 2. **闸门 + 证据预算**：低于阈值的片段直接丢弃、证据总字数封顶；**全部不达标就明确说"没有证据"**，而不是硬凑答案。
> 3. **上下文扩窗**：命中的往往只是一小段，所以带上同文件相邻片段；扩出来的字**也计入预算**。
> 4. **向量存储**：从 JSON 文本改成 float32 二进制（约 4KB/条，比 JSON 小 4 倍多），**读取侧双读**兼容老数据。
> 5. **向量库可插拔**：默认在内存里算余弦（零依赖）；配 `vector-store=pgvector` 就交给 PostgreSQL（**只存 chunk_id + 向量**，正文仍留 MySQL，因为关键词检索/扩窗/来源标注都要读文本）；PG 不可用**自动回落**。
> 6. **确定性知识问答**：把"必须先检索"从提示词里的**请求**变成代码里的**保证** —— 先检索、再带编号证据生成；没检索到就回退给 Agent。

RAG = Retrieval-Augmented Generation（检索增强生成）。流程：

```
上传文档 → 切成小段(chunk) → 用 Embedding 模型转成向量 → 存 kb_chunks 表
提问时   → 把问题也转成向量 → 在库里找最相似的若干段 → 塞进提示词交给模型作答
```

相关文件：`service/rag/EmbeddingService`（调 Ollama 的 `/v1/embeddings`，模型 `bge-m3`）、
`service/rag/TextSplitter`（中文语义切分）、`service/rag/RagService`（检索）、
`entity/KbChunk`、`entity/KbCollection`。

### 6.4 流式对话（SSE）

普通 HTTP 是"请求—一次性响应"；聊天要"一边生成一边显示"，用的是 **SSE（Server-Sent Events）**：
服务器保持连接，**一段一段**往前端推送。

本项目定义了 5 类事件，前端按类型渲染：

| 事件 | 含义 |
|---|---|
| `token` | 正文增量（一个字/词） |
| `reasoning` | 思考过程增量（部分模型有） |
| `sources` | 本轮参考的知识库来源文件名 |
| `done` | 结束（带 user_id / assistant_id） |
| `error` | 出错（连接仍是 200，前端显示"出错了…"） |

相关文件：`controller/ChatController`、`service/ChatService`（用 `SseEmitter`）、
`common/ChatStreamEvent`、`service/agent/ThinkSplitter`（把"思考"和"正文"拆开）。

> 前端按这 5 类事件的名字和结构逐字解析，因此后端事件格式必须严格保持一致。

## 第 7 章 前端怎么和后端对话

```
浏览器 React 组件
   │  调用 src/api/index.ts 里的函数（如 chatApi.stream(...)）
   ▼
src/api/client.ts   ← 统一封装 fetch；流式用 fetch + ReadableStream 逐块读
   │  请求 /api/xxx
   ▼
Vite 开发服务器（端口 5174）  ← vite.config.ts 里把 /api 代理到 http://127.0.0.1:8002
   ▼
后端 Spring Boot（端口 8002）
```

- **为什么用代理**：开发时前端 5174、后端 8002 是"跨域"的；让 Vite 把 `/api` 转发过去，
  浏览器就以为是同源，省掉跨域配置。生产环境则配 `app.cors.allowed-origins`。
- **必须写 `127.0.0.1` 而不是 `localhost`**：Windows 下 `localhost` 可能解析到 IPv6 的 `::1`，
  而后端只监听 `127.0.0.1`（IPv4），用 `localhost` 会连不上。
- 页面在 `src/pages/`，可复用零件在 `src/components/`，接口类型在 `src/types.ts`。

## 第 9 章 怎么把它跑起来（给初学者）

前置：装好 **JDK 21**、**Maven**、**Node.js**、**MySQL 8.4**、**Ollama**（并 `ollama pull qwen3:8b` 与 `bge-m3`）。

```bash
# 1) 建库（一次即可）
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS ipas_assistant DEFAULT CHARACTER SET utf8mb4;"
```

## 第 10 章 新手一定会踩的坑（本项目真实记录）

> **【本版本新增的三个"静默失败"坑 —— 比功能更值得记】**
> 1. **环境变量不生效**：`@ConditionalOnProperty` 读的是 **Spring 配置属性**，而环境变量只有在 `application.yml` 里**声明过**（`xxx: ${ENV_NAME:default}`）才会被映射过去。漏写这行**不报错、不警告**，只是**静默失效**（实际踩了两次）。
> 2. **查询参数名也是契约**：后端写**裸 `@RequestParam Long collectionId`** 时，要求的名字是**编译后的驼峰名**；而前端（与 Python 原版）发的是 `collection_id` → 后端返回 **422**。更糟的是前端 `.catch(() => setData(null))` 把错误吞掉，页面只剩空白、还会误报"这个库没有文档"。
> 3. **配置文件格式错了只警告**：`conf/settings.xml` 里被写进了一段 `pom.xml`，Maven 只打一句 WARNING 就**忽略整个文件** —— 里面配的镜像从未生效。
>
> **共同结论：改完外部配置或契约，要验证「它真的生效了」，而不是「没报错」。**

| 坑 | 现象 | 一句话解法 |
|---|---|---|
| `@RequestBody` 没配 `@Valid` | DTO 上的校验注解**静默失效** | 每个 `@RequestBody` 都写 `@Valid` |
| `@RequestParam` 的 `@Min/@Max` 不生效 | 越界仍返回 200 | 控制器**类**上加 `@Validated` |
| 时间存/查差 8 小时 | 接口对、Navicat 里不对 | JDBC 用 `connectionTimeZone=LOCAL&preserveInstants=false` |
| 字符集报错 | `Unsupported character encoding 'utf8mb4'` | JDBC 参数写 `characterEncoding=UTF-8`（Java 名） |
| 端口被"顶掉" | yml 写 8002 却去抢别的端口 | 用 `run.sh/run.bat`（会清 `SERVER_PORT` 环境变量） |
| `spring-boot:run` 改了代码像没生效 | 旧 JVM 还占着端口 | 重启前用 `netstat` 查 PID 并结束 |
| 前端 `npm install` 崩溃/卡住 | 退出码 `-1073740791` 或长时间不动 | 用 `--no-audit --no-fund --registry https://registry.npmmirror.com` |
| 大型数被写成科学计数法 | 返回 `1.7E9` | `JacksonConfig` 里用 `toPlainString()` |

## 第 11 章 给初学者的建议阅读顺序

1. 本文（建立全局图景）。
2. `docs/项目结构清单.md`（知道每个目录/包干什么）。
3. `backend/pom.xml` 顶部注释（理解依赖与版本为什么这么选）。
4. `application.yml`（看配置项与它对应的功能）。
5. **从一条最简单的链路读代码**：`TodoController` → `TodoService` → `TodoRepository` → `entity/TodoItem` → `dto/TodoDtos`。
6. 再读复杂链路：`ChatController` → `ChatService` → `service/agent/AgentFactory` → `service/llm/ChatModelFactory`。
7. 最后读 `security/` 与 `service/rag/`。

## 附：术语小词典

| 术语 | 白话解释 |
|---|---|
| Bean | Spring 容器里被管理的对象 |
| 依赖注入 DI | 对象需要什么，Spring 自动"递"给它，不用自己 new |
| 注解 | 以 `@` 开头的"标签"，框架据此做事（如 `@Service` 表示"这是个业务组件"） |
| ORM | 把 Java 对象和数据库表互相转换的技术 |
| JWT | 登录后发的"电子通行证"字符串 |
| Embedding | 把文字变成一串数字（向量），用于算"语义相似度" |
| RAG | 让 AI 先"查资料"再回答 |
| SSE | 服务器持续往浏览器推送数据的机制（聊天流式就靠它） |
| Agent | 能自己决定"先调哪个工具、再回答"的 AI |
| 契约 | 前后端约定好的接口格式；本项目用测试把它固化下来，避免被无意改坏 |
